OpenResponses 2.9 is a native developer playground for the OpenAI Responses API. It requires no separate OpenResponses account. Explore Demo is offline; live testing requires an authorized OpenAI API key with model/tool access and bills that account. Any reviewer API credential must be supplied privately in App Store Connect, not in public metadata.

The key is stored in iOS Keychain and sent to OpenAI for authentication. Before the first live request, the app presents its data-sharing notice and requires Allow & Send. Selected prompts, attachments and tool results are transmitted for processing; local history and optional remote storage are separate.

New in 2.9 (how tool activity is shown; no new permissions, services or data collection):
• Each tool step under an answer (web search, file search, Code Interpreter, image generation, MCP, the in-app browser) shows a spinner while it runs and Completed or Failed when it ends. Tapping a step shows what it did; a Code Interpreter step shows the Python that OpenAI ran.
• A Code Interpreter chart appears once (it could appear two or three times), text after a tool call starts a new paragraph, reasoning summaries render their formatting, and the Computer Use notice says it drives only the app's own browser.
• The App Store previews are screen recordings of this build.

In the app since 2.8: Local Python (Settings → Model, with a GPT-6 or GPT-5.6 model selected). The assistant can write Python; a sheet shows the code and nothing runs until the user taps Run. The interpreter (Pyodide 314.0.7, CPython compiled to WebAssembly, MPL-2.0) ships in the app bundle; no code or packages are downloaded or installed. It runs in a WKWebView whose content rules block every load except the bundled runtime: Python standard library only, no network, no file access, a fresh namespace each run, 30-second limit. Try: "use Python to find the 30th Fibonacci number".

Suggested review:
1. Explore Demo, then configure an authorized test key for live requests.
2. Select an account-available model, send a greeting, accept the first-send notice and inspect streaming, activity and request details.
3. Send a follow-up and switch chats; existing history should remain available.
4. Turn on Code Interpreter, ask for a pie chart of a few numbers, and tap the Code Interpreter step under the answer to see its code.
5. Try Web Search and inspect sources. Attach a small file and observe vector-store indexing if using file search.
6. Open Settings → Model → API Workbench to inspect raw requests, events, exports, token counting and compaction.
7. Open voice mode, grant microphone access and speak for multiple turns. Settings → Model → Voice switches between GPT Realtime 2.1 and GPT-Live 1.

Computer Use is opt-in and operates an on-device WKWebView, with no separate local-network browser bridge. DOM/screenshot actions share cancellation, deadlines and action limits. API-provided safety prompts may be denied; not every action has a separate approval.

MCP setup/discovery uses OpenAI-hosted MCP; the endpoint and server authentication may be sent to OpenAI so it can connect. Supported providers use the iOS system browser for sign-in, and monday.com, Airtable, Intercom and Vercel return through https://gunzino.me/openresponses/oauth/callback.html, a static page that forwards the result to the app's openresponses:// callback. Apple Calendar/Reminders/Contacts and Notion are optional and require their own permissions or credentials.
