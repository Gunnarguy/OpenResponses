OpenResponses 2.6 is a native developer playground for the OpenAI Responses API. It requires no separate OpenResponses account. Explore Demo is offline; live testing requires an authorized OpenAI API key with model/tool access and bills that account. Any reviewer API credential must be supplied privately in App Store Connect, not in public metadata.

The key is stored in iOS Keychain and sent to OpenAI for authentication. Before the first live request, the app presents its data-sharing notice and requires Allow & Send. Selected prompts, attachments and tool results are transmitted for processing; local history and optional remote storage are separate.

Suggested review:
1. Explore Demo, then configure an authorized test key for live requests.
2. Select an account-available model, send a greeting, accept the first-send notice and inspect streaming, activity and request details.
3. Send a follow-up and switch chats; existing history should remain available.
4. Try Web Search and inspect sources. Attach a small file and observe vector-store indexing if using file search.
5. Open Settings → Model → API Workbench to inspect raw requests, events, exports, token counting and compaction.
6. Open voice mode, grant microphone access and speak for multiple turns. Test mute and return to listening after the answer.

Computer Use is opt-in and operates an on-device WKWebView, with no separate local-network browser bridge. DOM/screenshot actions share cancellation, deadlines and action limits. API-provided safety prompts may be denied; not every action has a separate approval. Stopping cannot reverse a website mutation already received.

MCP setup/discovery uses OpenAI-hosted MCP. The endpoint and server authentication may be sent to OpenAI so it can connect. Private OAuth services may need separate account setup. Apple Calendar/Reminders/Contacts and Notion are optional and require their own permissions or credentials.

Batch exports save complete available output/error files. Fine-tuning imports reviewed text-chat JSONL and explains restricted service availability; exporting one chat is only a draft. Paid jobs are not necessary to inspect these screens. Retained Assistant JSON can be imported into Responses presets; retired live Assistants operations are disabled. Arbitrary Workbench tool schemas do not execute arbitrary shell commands on the iPhone.


MCP Connections: Settings → MCP opens the new account library. Supported providers use the iOS system browser for account sign-in; tool discovery is separate and uses the reviewer’s OpenAI API account after consent. Public entries need no provider account. The catalog explicitly identifies providers requiring developer registration or different callback setup; those entries do not claim working sign-in. Existing direct Notion integration keys remain under legacy management.
Workbench request drafts persist securely; malformed schemas are rejected locally. Voice starts a separate session and does not inherit chat history/tools.
